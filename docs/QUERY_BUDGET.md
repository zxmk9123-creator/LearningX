# DB 조회 예산 (요청당 SQL 문 수)

운영 API(Northflank US-Central)와 DB(Neon 싱가포르)는 서로 다른 지역에 있다. 그래서 SQL 문 하나가 왕복 약 0.2초다. 학생 요청은 아래 예산을 넘지 않는다. 예산은 `tests/test_query_budget.py`가 지킨다.

여기서 세는 것은 앱이 보내는 SQL 문이다. 실제 왕복은 연결 확인(pre-ping), BEGIN, COMMIT이 더해져 약 3회 더 많다.

## 측정 (PostgreSQL, 2026-11-25)

| 요청 | 이전 | 현재 | 실용 하한 | 운영 예상(×0.2초, +3회) |
|---|---|---|---|---|
| 질문 보내기(코칭) | 33 | 14 | 14 | 7.2초 → 3.4초 |
| 고쳐 쓰기(코칭) | 36 | 17 | 17 | 7.8초 → 4.0초 |
| 고쳐 쓰기(차단) | 26 | 12 | 12 | 5.8초 → 3.0초 |
| 실시간 화면 폴링(학생) | 6 | 3 | 3 | 1.8초 → 1.2초 |
| 내 질문 폴링 | 17 | 11 | 약 6 | |

질문 요청의 코칭 AI 호출 시간은 여기에 더해진다.

## 실용 하한의 근거 (고쳐 쓰기, 코칭)

코드 구조를 바꾸지 않고(저장 프로시저, 여러 쓰기를 묶는 CTE 없이) 기능을 그대로 지키려면 아래 17개가 필요하다.

| 단계 | 문 수 | 이유 |
|---|---|---|
| 로그인 사용자 확인 | 1 | 비활성화된 계정을 즉시 막는다(토큰만 믿지 않음) |
| 수업 접근 확인 | 1 | 참여·수업·채팅 상태·코스 멤버십·삭제 여부·정책·송출 쪽·코스 소유자를 한 번에 읽는다 |
| 질문 확인 | 1 | 질문, 인용, 현재 버전을 한 번에 읽는다 |
| 대화 이력 | 1 | 처음 질문, 고쳐 쓴 횟수 |
| 교안·코스 | 1 | 근거 지문과 코스 정책 |
| 학습목표 | 1 | 수업에 연결된 목표 버전 |
| 판정 원장 조회·기록 | 2 | 같은 질문은 같은 판정. 기록은 `ON CONFLICT DO NOTHING` 한 번 |
| 수업 잠금 | 1 | 종료·채팅 잠금과 쓰기의 순서를 정한다(채팅 상태를 함께 새로 읽음) |
| 질문 잠금 | 1 | 제출과 고쳐 쓰기의 순서를 정한다 |
| 쓰기 | 5 | 질문 갱신, 버전 기록, 현재 버전 갱신, 적합성 판정, 감사 기록 |
| 이전 판정 정리 | 1 | 대기 중이던 적합성 판정을 무효로 한다 |
| 반복 질문 규칙 | 1 | 최근 질문과 비교한다 |

이보다 더 줄이려면 쓰기를 한 문장으로 묶거나 잠금 두 개를 합쳐야 한다. 그러면 잠금 순서(수업 행 → 질문 행) 보장이 약해지고 코드가 DB 전용 문법에 묶인다. 남은 지연을 크게 줄이는 방법은 API와 DB를 같은 지역에 두는 것이다(`NORTHFLANK_SINGAPORE_MIGRATION.md`).

## 줄인 방법

1. **요청 안에서 다시 읽던 행.** SQLAlchemy의 identity map은 약한 참조라서, 아무도 붙잡지 않은 객체는 다음 `db.get` 때 다시 읽혔다. 접근 확인에서 읽은 객체를 요청 끝까지 붙잡는다(`security.keep`).
2. **합친 읽기.**
   - 참여 확인, 수업, 채팅 상태, 멤버십, 삭제 여부, 정책, 송출 쪽, 코스, 소유자를 한 문장으로 읽는다.
   - 질문, 인용, 현재 버전을 한 문장으로 읽는다.
   - 교안, 코스, 소유자를 한 문장으로 읽는다.
   - 학습목표 연결과 버전을 한 문장으로 읽는다.
   - 처음 질문과 고쳐 쓴 횟수를 한 문장으로 읽는다.
   - 실시간 폴링은 접근 확인, 송출 쪽, 채팅 상태, 열람 허용 쪽을 한 문장으로 읽는다.
3. **잠금.** 수업 행 잠금과 채팅 상태 재확인을 한 문장(`FOR UPDATE OF class_sessions`)으로 합쳤다. 채팅 상태는 잠금과 함께 새로 읽는다.
4. **원장 기록.** SAVEPOINT, INSERT, RELEASE 세 번을 `INSERT … ON CONFLICT DO NOTHING RETURNING` 한 번으로 바꿨다.
5. **적합성 판정.** 규칙 판단이 끝난 뒤에 세션에 추가해 INSERT 한 번으로 쓴다. 이전에는 INSERT 뒤에 UPDATE가 따로 나갔다. 새 질문은 이전 판정·버전 조회를 건너뛴다.
6. **조기 확인.** 잠금 전에 채팅이 닫혔는지 보는 조기 확인은 접근 확인 때 읽은 값을 쓴다. 쓰기 직전에는 언제나 잠금과 함께 다시 읽는다.
