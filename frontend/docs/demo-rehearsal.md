# LearningX 발표용 데모 리허설 — 같은 브라우저 두 탭

이 문서는 **Draft PR #7 전용**으로, 실제 강의 자료가 아닌 공개 가능한 가상 교안만 사용합니다. 데모의 수준 분류는 키워드 규칙이며 AI 모델을 호출하지 않습니다. 강의 파일 내용은 실제 분석하지 않습니다.

## 시작 직전 체크리스트

1. 교수자 탭(`app.html?demo=faculty`)에서 **데모 초기화**를 누른다. 수업 코드, 기존 질문, 새 질문 뱃지, 승인 정보를 지웠는지 확인한다.
2. 같은 브라우저 프로필의 새 탭에 `app.html?demo=student`를 연다. **다른 기기/브라우저 프로필과는 공유되지 않는다.**
3. 교수자 탭에서 공개 가능한 임의의 PDF/PPTX를 선택한다. 파일명·크기·SHA-256이 **실제 계산**되는 동안의 에이전트 단계를 보여 준다. **데모 모드: 올린 파일은 분석하지 않았습니다. 아래는 예시 교안의 분석 결과입니다.** 문구를 강조한다.
4. 가상 교안 p.1만 승인하고 수업을 시작한다. 6자리 코드를 학생 탭에 전달한다. p.2/p.3은 품질은 통과했지만 **교수자가 승인하지 않은 상태**로 남겨둔다.
5. 학생 탭에서 코드 입력 → 아래 고정 질문 중 하나를 선택해 직접 입력 → 추천 줄기 칩 선택 → 학생이 `___`를 채워 제출 → 교수자 탭의 **새 질문 뱃지와 익명 질문** 및 프로젝터 화면 확인.

## 고정 리허설 질문 3개

| 단계 | 학생이 입력할 질문 (그대로 복사) | 예상 분류 | 첫 추천 질문 칩 | 허용 출처 |
|---|---|---|---|---|
| 1 | 의제설정 이론은 무엇을 설명하나요? | **얕은** | 비교하기 · `___와 ___는 어떤 점이 다를까요?` | **p.1** |
| 2 | 뉴스 보도와 의제설정 이론의 차이는 무엇인가요? | **중간** | 적용하기 · `___를 ___ 상황에 적용하면?` | **p.1** |
| 3 | 왜 뉴스가 의제설정에 영향을 준다고 볼 수 있나요? | **깊은** | 조건 바꾸기 · `___라는 조건을 바꾸면 ___는 어떻게 달라질까요?` | **p.1** |

검증 방법: `node frontend/tests/demo_rehearsal.mjs`. **실제 `assets/demo-adapter.js`의 `levelOf`, `questionStems`, `evidence`를 실행**하여 분류와 p.1만 인용하는지 비교한다.

**발표 주의:** 분류는 문장 의미를 이해하는 방식이 아니라 키워드 우선순위(깊은 > 중간 > 얕은)로 결정한다. 즉석 질문은 기대와 다르게 분류될 수 있으므로 위 세 문장을 그대로 사용한다. 모든 출처 칩은 **가상 교안의 교수자 승인 표시**이며 실물 강의 근거도 암호학적 서명도 아니다.

- 로컬에서 시작할 때에도 데모 초기화 후 **교수자→학생→익명 질문→프로젝터** 순서로 사전 점검한다.

## 실서버 경계

가상 NIT JSON은 누구나 다운로드할 수 있고, 데모는 이를 브라우저에서 필터링한다. **실제 교안에는 사용할 수 없는 방식**이다. 운영 서버의 학생 API는 **교수자 서명 승인 블록만 JSON 응답 본문에 포함**해야 하며, DOM에 보이지 않는다는 이유로 안전 판정을 내리지 않는다. 상세 테스트 계약은 [demo-session-api-contract.md](demo-session-api-contract.md)에 정리했다.
